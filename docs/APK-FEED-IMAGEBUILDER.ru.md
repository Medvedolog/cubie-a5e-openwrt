# Cubie A5E — подписанный APK-feed и ImageBuilder из GitHub Releases

**Статус:** механизм добавлен 05.11.2026; успешная сквозная публикация
и установка на физической плате ещё должны быть подтверждены CI/тестером.

## Почему здесь не подходит официальный OpenWrt Snapshot

Порт использует PR [openwrt/openwrt#23296](https://github.com/openwrt/openwrt/pull/23296)
с отдельным `sunxi/cortexa55`, Wi-Fi DTS, AIC8800 и собственным kernel ABI.
Официальный OpenWrt Snapshot может содержать другое ядро, конфигурацию
и `kmod` ABI. Совпадения номера Linux недостаточно.

## Как организованы выпуски

Для каждого успешного `Build image (OpenWrt from source)`:

1. Из `staging_dir/packages/sunxi/` копируются **все реально собранные
   APK**, исходный **подписанный** `packages.adb` и `public-key.pem`.
   Подпись не пересоздаётся ключом публикационного workflow.
2. В GitHub Releases создаётся неизменяемый pre-release
   `cubie-a5e-pkgs-<Git SHA12>-<GitHub run_id>-<attempt>`. Индекс и каждый APK-файл —
   отдельные assets в корне релиза, поэтому APK может скачивать пакеты
   непосредственно с GitHub (HTTP 302 обрабатывается клиентом).
3. В опубликованном образе `/etc/apk/repositories.d/distfeeds.list`
   заранее задан адрес:
   `https://github.com/Medvedolog/cubie-a5e-openwrt/releases/download/cubie-a5e-pkgs-<SHA12>-<RUN_ID>-<ATTEMPT>/packages.adb`.
   Официальные Snapshot feeds исключены.
4. ImageBuilder собирается **из того же самого** дерева OpenWrt и
   `.config`, с `CONFIG_IB=y`, `CONFIG_IB_STANDALONE` отключён.
   В архиве `repositories` заменён на тот же постоянный адрес и
   `keys/public-key.pem` соответствует индексу. При `make image` базовый
   профиль Cubie A5E автоматически получает AIC8800 SDIO и firmware,
   переносится лабораторный `uci-defaults` и комплект recovery-скриптов;
   в новых образах принудительно сохраняются ключ и закреплённый feed.
5. В rolling release `cubie-a5e-test` добавляется архив
   `*imagebuilder*.tar.zst` и публичный ключ; все APK живут в своём
   неизменяемом releases/tag-репозитории. В тегированных релизах
   ImageBuilder наследуется из испытанного rolling build.

**GitHub Pages не требуется.** Для каждого запуска и попытки адрес отдельный,
поэтому новые сборки не ломают возможность `apk add` в старой прошивке. Номер запуска важен: один и тот же коммит можно пересобрать с другими feeds или входным OpenWrt SHA, поэтому привязка только к Git SHA была бы недостаточной.

## Использование на A5E

```sh
apk update
apk add kmod-usb-net-qmi-wwan
```

Команда сработает только если этот пакет **присутствовал в собранном
наборе** данного релиза. Непостроенные пакеты нельзя получить из нашего
feed только по названию. Для дополнительных драйверов добавляйте
`CONFIG_PACKAGE_имя=m` в `config/diffconfig` и пересобирайте релиз.

Для работы с ImageBuilder на Linux x86-64:

```sh
tar --zstd -xf openwrt-imagebuilder-*.tar.zst
cd openwrt-imagebuilder-*/
make info
make image PROFILE=radxa_cubie-a5e PACKAGES="luci kmod-nvme"
```

Набор пакетов в `PACKAGES` должен соответствовать реальной сборке
(нужные дополнительные модули предварительно включаются как `=m`).

## Предупреждение о DRAM при использовании ImageBuilder

Сформированный ImageBuilder использует универсальную конфигурацию
U-Boot. На платах, для которых нужны индивидуальные TPR11/TPR12
(например, Micron 4 ГБ с профилем M6), такая прошивка **может не
загрузиться**. Для аппаратных испытаний сначала используйте готовые
SD-образы с соответствующими DRAM-профилями. Автоматическая сборка
произвольных DRAM-профилей в ImageBuilder ещё не реализована.

Отдельно для установки на работающее устройство базовая конфигурация
уже содержит AIC8800, а дополнительные драйверы USB-модемов
`kmod-usb-net-qmi-wwan`, `kmod-usb-net-cdc-mbim`,
`kmod-usb-serial-option`, `kmod-usb-acm` и другие из
`config/diffconfig` собираются с `=m`, не включаясь в rootfs.

## Подписание

`.github/workflows/build.yml` берёт EC P-256 PEM из секрета Actions
`APK_SIGN_KEY`, когда он задан. Использовать **один постоянный ключ**
для публичных выпусков желательно; публиковать нужно только его
открытую часть. При отсутствии секрета OpenWrt генерирует одноразовый
ключ этой сборки: feed и образ остаются согласованными, но это
предварительные тестовые пакеты, без гарантии постоянства ключа между
перепрошивками. Приватный ключ никогда не загружается в артефакты.

## Ограничения

- Это полный набор **собранных**, а не всех возможных OpenWrt APK.
- `kmod` разных Git-коммитов/версий kernel ABI смешивать запрещено.
- GitHub Releases и его CDN должны быть доступны с самого роутера.
- Публикация завершается только после полной загрузки всех assets.
  Неполный репозиторий остаётся в черновике (draft).
- Проверка реального `apk update && apk add` на A5E пока необходима.
