# OpenWrt для Radxa Cubie A5E (Allwinner A527) со встроенным Wi-Fi

**[English version](README.md)**

Чистая сборка OpenWrt для Radxa Cubie A5E: OpenWrt main с поддержкой A527,
которая пока на рецензии, собранный из исходников на GitHub Actions, со
встроенным Wi-Fi (AIC8800D80, SDIO), обоими гигабитными портами, USB и
M.2 NVMe.

> **Статус: аппаратные тесты начаты (13.10.2026).** На плате Cubie A5E V1.1 / Micron 4 ГБ подтверждена загрузка ext4 с microSD; AIC8800D80 иногда успешно загружает firmware и создаёт PHY, а иногда останавливается на ошибке SDIO `-110`. **Стабильная точка доступа и полное восстановление пока не подтверждены.**
> Фактические результаты и открытые проблемы: [полевой журнал Wi-Fi](docs/AIC8800-SDIO-WIFI.ru.md).

## Почему сборка из исходников

В OpenWrt пока нет Allwinner A527. Поддержка на рецензии:
[openwrt/openwrt#23296](https://github.com/openwrt/openwrt/pull/23296)
«sunxi: add support for A527/T527 boards» от мейнтейнера sunxi (новая
подцель `cortexa55`, профиль `radxa_cubie-a5e`). Проект собирает эту ветку
на зафиксированном коммите и добавляет то, чего в ней нет для этой платы:
драйвер Wi-Fi AIC8800 (из ImmortalWrt), последовательность включения Wi-Fi,
запасной набор параметров DRAM для разных ревизий, пакеты NVMe
([docs/PORTING-NOTES.md](docs/PORTING-NOTES.md), по-английски). Когда PR
примут, сборка перейдёт на официальный snapshot, а здесь останется только
драйвер Wi-Fi — как в проекте для Orange Pi Zero 3.

Следствие: **kmod с downloads.openwrt.org к этому ядру не подходят.**
Все kmod для него будут опубликованы, подписанными, в собственном
apk-репозитории проекта (в плане, см. ниже).

## Статус

| Функция | Статус |
|---|---|
| Образ собирается в CI | да; структурные проверки CI проходят, не заменяют тесты платы |
| Загрузка с microSD | **подтверждена:** ext4 rootfs на Micron 4 ГБ, remount rw |
| eth0 (LAN, 192.168.1.1) / eth1 (WAN, DHCP) | конфигурация задана; оба физических порта отдельно не верифицированы |
| Wi-Fi точка доступа / клиент, 2,4 ГГц | не проверено |
| Wi-Fi 5 ГГц / AIC8800D80 | **частично:** SDIO/firmware/PHY на удачном старте; на другом старте `-110`; клиент/AP/DHCP не проверены |
| Порты USB 2.0 | не проверено |
| USB 3.0 SuperSpeed | в этом образе нет (см. ниже) |
| M.2 NVMe | не проверено |
| reboot / выключение / sysupgrade | не проверено |

**Ревизии платы и память.** Владельцы сообщают, что mainline U-Boot
грузит не все ревизии: параметры DRAM зависят от чипов памяти. В этой
сборке добавлен запасной набор параметров и по образу на каждый
известный профиль памяти (`dram-universal`, `dram-micron-4g-m6`, …); если
плата всё равно не стартует, нужен лог с UART (см.
[docs/COMMUNITY-FINDINGS.md](docs/COMMUNITY-FINDINGS.md#1-boot-dram-parameters-depend-on-the-board-revision)).

**USB 3.0 или NVMe.** В A527 одна combo-PHY на слот M.2 и порт USB 3.0
(аппаратное ограничение). Этот образ отдаёт её PCIe (M.2 NVMe), как
BSP Radxa по умолчанию; порты USB-A работают как USB 2.0. Вариант с USB3
запланирован ([PORTING-NOTES §4](docs/PORTING-NOTES.md#4-usb-what-works-and-what-does-not)).

## Скачать

- Тестовые сборки: пререлиз
  [cubie-a5e-test](../../releases/tag/cubie-a5e-test), заменяется каждой
  сборкой рабочей ветки. **Образы экспериментальные: ext4 загружался, но стабильность Wi-Fi не доказана.**
- Позже: «скользящий» `cubie-a5e-snapshot-latest` из `main` и
  фиксированные релизы с описанием (`docs/releases/`).

**Сначала прошивайте `…-dram-universal-…`**: один образ для всех ревизий
платы, как у Armbian (параметры DRAM mainline на 936 МГц и запасной набор).
Остальные образы (`…-dram-micron-4g-m6-…`, …) — запасные, под конкретную
память, для плат, которые с ним не стартуют; отличаются только настройками
DRAM в U-Boot.

## Устройство репозитория

| Путь | Что |
|---|---|
| `target/`, `package/` | файлы, добавляемые в дерево OpenWrt: последовательность включения Wi-Fi (DTS), запасной набор DRAM в U-Boot, пакет `aic8800` |
| `patches/openwrt/` | изменения файлов дерева OpenWrt (возможность PCI у подцели) |
| `config/diffconfig` | конфигурация сборки |
| `scripts/check-image.py` | проверки собранного образа (DTB в FIT, rootfs, конфиг ядра) |
| `.github/workflows/build.yml` | сборка: PR #23296 на зафиксированном коммите, наши файлы, `make`, проверки |
| `docs/` | [журнал AIC8800/SDIO](docs/AIC8800-SDIO-WIFI.ru.md), [ручной recovery](docs/AIC8800-RECOVERY.ru.md), [план испытаний](docs/TEST-PLAN.md), [заметки о портировании](docs/PORTING-NOTES.md), [находки сообщества](docs/COMMUNITY-FINDINGS.md), [сборка на GitHub](docs/GITHUB-ACTIONS-GUIDE.ru.md) |

Сборка идёт на раннерах GitHub или на своём (self-hosted) раннере —
параметр `runner` при ручном запуске. Пакеты подписываются секретом
репозитория `APK_SIGN_KEY` (закрытый EC-ключ P-256); без него используется
одноразовый ключ и ничего не публикуется.

## Что уже выяснено про Wi-Fi

- Физический контроллер microSD — `4020000.mmc`, AIC8800 — `4021000.mmc`. Имена `mmc0/mmc1` меняются между загрузками; по ним нельзя выбирать устройство для сброса.
- На успешном старте скорость SDIO AIC8800 составила **33,33 МГц**, несмотря на ограничение DTS 35 МГц; принудительные 150 МГц в драйвере отключены.
- MAC встроенного Wi-Fi `fc:23:cd:03:8e:78` **не менялся на проверенных перезагрузках**. UCI-привязка по MAC и удаление старых дубликатов `radioX` реализованы на тестовой ветке; испытание исправленного образа продолжается.
- Добавлен **ручной** `aic8800-recover --check/--run` по образцу нашего OPIZ3. Переподключает только `4021000.mmc`, но на железе пока не испытан. Запускать `--run` только с UART/проводной связью, не через Wi-Fi.
- Причина firmware timeout `-110` ещё не установлена. Следующие отдельные опыты: 25 МГц SDIO, BLDO1, `mmc-pwrseq` и MMC recovery.

См. [анализ и сравнение с OPIZ3, ImmortalWrt, Armbian](docs/AIC8800-SDIO-WIFI.ru.md), [инструкцию recovery](docs/AIC8800-RECOVERY.ru.md) и [план тестов](docs/TEST-PLAN.md).

## План

Полный план с задачами и статусом: [docs/ROADMAP.md](docs/ROADMAP.md) (по-английски).

1. Первый образ, который собирается, — готов (пререлиз `cubie-a5e-test`).
2. Первая загрузка на железе: оба Ethernet, USB, NVMe, перезагрузка,
   sysupgrade.
3. Wi-Fi: точка доступа и клиент, 2,4 и 5 ГГц, WPA2/WPA3, холодный старт.
4. Свои SDK, ImageBuilder и подписанный apk-репозиторий со всеми kmod этого
   ядра; исправления драйвера через `apk upgrade`.
5. Состав образа как в проекте для Orange Pi Zero 3; первая загрузка с
   точкой доступа «A5E» и предупреждением в LuCI про пароль.
6. План тестов, ветка `main`, бета-релизы.
7. Аудит и исправление драйвера AIC8800.
8. Один образ для любой памяти (несколько наборов DRAM в U-Boot).
9. Вариант образа с USB 3.0.
10. Upstream: отчёты и исправления для openwrt/openwrt#23296; после слияния —
    официальный snapshot, а отсюда только драйвер Wi-Fi.
